한국 금융 앱 토스(Toss)의 화면 스타일을 따라 모바일 화면을 만들 때 쓰는 비공식 레퍼런스예요. 값은 토스가 npm에 공개한 디자인 시스템 패키지(`@toss/tds-colors`, `@toss/tds-mobile`)와 토스가 발표한 원칙에서 가져왔어요.

## 먼저 지킬 것

- 이 시스템으로 만든 화면에 **토스의 이름, 로고, 앱 아이콘을 넣지 마세요.** 토스 공식 화면처럼 보이게 만드는 용도가 아니라, 토스의 방식(단순함, 한 화면 한 가지, 쉬운 말)을 빌려 쓰는 용도예요.
- 예시 콘텐츠는 실제 은행·회사 이름 대신 "생활비 통장", "월급 통장"처럼 일반 명칭을 쓰세요.
- 모든 화면은 **모바일 단일 칼럼**(기준 폭 375~430px)으로 그리세요. PC에서는 가운데에 모바일 폭 칼럼을 두고 바깥을 `pcScreenBg`로 채우세요.

## 제품 원칙

화면을 설계하기 전에 이 다섯 가지로 걸러내세요. 토스가 공개한 Product Principles예요.

- **One Thing for One Page.** 한 화면은 메시지 하나만 전해요. 큰 제목 하나, 입력이나 목록 하나, 하단 버튼 하나가 기본이에요. 정보가 많으면 화면을 나누세요.
- **Easy to Answer.** 모든 질문은 3초 안에 답할 수 있어야 해요. 자유 입력보다 고르기(목록, 칩, 휠)를 쓰고, 이미 아는 값은 미리 채우세요.
- **Value First, Cost Later.** 사용자가 얻는 것(혜택, 결과, 금액)을 먼저 크게 보여주고, 본인인증·약관·정보 입력은 그다음에 요청하세요.
- **Casual Concept.** 금융 용어를 사용자에게 넘기지 말고 실제로 겪는 결과로 바꿔 말하세요("만기일시상환" → "끝날 때 한 번에 갚기").
- **Minimum Features.** 이 기능 없이 목표를 절대 이룰 수 없는지 다시 묻고, 옵션은 줄이고 좋은 기본값을 주세요.

핵심 가치는 **Simplicity**예요. 따로 배우지 않아도 바로 이해되는 상태를 말해요. 깔끔한 모양은 그 결과일 뿐이에요.

## 콘텐츠 기초

자세한 규칙과 예문은 "보이스와 톤" 섹션에 있어요. 요약하면:

- **모든 문구는 해요체**로 쓰세요. "~합니다", "~하시겠습니까?"는 쓰지 않아요.
- **능동형, 긍정형**으로 쓰세요. "안 돼요" 대신 "~하면 할 수 있어요".
- 화면 제목은 **질문형**("누구에게 보낼까요?") 또는 **결과형**("50,000원을 보냈어요")으로 쓰세요.
- 버튼은 **짧은 동사**("다음", "확인", "보내기"). 결과가 중요하면 구체적으로("50,000원 보내기").
- 다이얼로그의 **왼쪽 버튼은 "닫기"** 로 통일하세요.
- 숫자는 세 자리마다 쉼표, 단위는 붙여 쓰세요: `1,250,000원`, `연 3.5%`.
- 느낌표, 과장, 겁주는 표현("지금 안 하면 사라져요!")은 쓰지 않아요.
- 이모지는 장식으로 뿌리지 말고, 목록 아이콘이나 빈 상태 그림처럼 **아이콘 자리에 하나씩**만 쓰세요.

## 시각 기초

### 색

- 화면 바탕은 `background`, 글자와 아이콘은 그레이 스케일이에요. **화면의 90% 이상을 무채색으로** 채우세요.
- **강조색은 `blue500` 하나**예요. 주요 버튼, 링크, 입력 커서, 켜진 스위치, 선택 상태에만 쓰세요. 한 화면에 파란 fill 버튼은 하나만 두세요.
- 글자 위계: 제목·금액 `grey900` → 본문·목록 제목 `grey800` → 약한 본문 `grey700` → 부제·설명 `grey600` → 캡션·플레이스홀더 `grey500`. 비활성은 `grey400`.
- `grey500`은 라이트 테마에서 `background` 대비 3.0:1이라 **필수 정보 글자에는 쓰지 마세요.** 플레이스홀더, 날짜, 보조 캡션만 써요.
- 흰 글자를 `blue500` 위에 올리면 3.7:1이에요(토스 원본 값). 버튼처럼 17px 굵은 글자에만 쓰고, 작은 글자를 파란 면 위에 올리지 마세요.
- 섹션은 테두리 대신 **16px `greyBackground` 띠**로 나누고, 목록 항목 사이는 **왼쪽 24px 들여쓴 0.5px `hairline`** 선으로 나누세요.
- 의미색: `red500` 오류·위험·삭제, `green500` 성공·완료, `orange500` 경고. 의미가 있을 때만 쓰세요.
- **금융 데이터는 한국 관례**를 따르세요. 오르면 `red500`, 내리면 `blue500`이에요. 반드시 `+`/`−` 부호를 함께 붙이세요.
- teal, purple, yellow 등 보조 팔레트는 차트와 카테고리 구분, 일러스트에만 쓰세요.
- 다크 테마는 단순 반전이 아니에요. 같은 토큰 이름을 쓰면 알맞은 값으로 바뀌어요(`background` `#17171c`, 층이 올라갈수록 밝아짐: `layeredBackground` → `floatBackground`).

### 글자

- 서체는 토스 전용 **Toss Product Sans**(비공개)예요. 이 시스템은 공개 대체 서체 **Pretendard**(400·500·600·700)를 실어 두었어요. `--font-sans` 하나만 쓰세요.
- 크기는 **기본 스케일 7단계**만 먼저 쓰세요: `t1` 30 · `t2` 26 · `t3` 22 · `t4` 20 · **`t5` 17(본문)** · `t6` 15 · `t7` 13. 보조 스케일 `st1`~`st13`은 꼭 필요할 때만.
- 굵기 4단계: 제목·금액 700, **버튼 600**, 목록 제목·설명 500, 본문·캡션 400.
- 자주 쓰는 조합은 역할 스타일로 있어요: `amount-hero`, `page-title`, `dialog-title`, `list-title`, `button-label`, `body`, `description`, `toast`, `caption`, `eyebrow`.
- 화면 제목은 내비게이션 바가 아니라 **본문 첫머리에 크게**(`page-title`, 왼쪽 정렬, `gutter` 24px) 쓰세요.
- **금액이 화면의 주인공**이면 `amount-hero`로 가장 크게 쓰고, 설명은 `t6`~`t7`로 작게 쓰세요.
- 글자는 왼쪽 정렬이 기본이에요. 가운데 정렬은 완료·결과 화면과 빈 상태에만 쓰세요.

### 간격과 레이아웃

- 화면 좌우 여백은 `gutter`(24px), 하단 고정 버튼 영역은 `gutter-cta`(20px)예요.
- 화면 골격: **제목 블록(Top) → 콘텐츠 → 하단 고정 버튼(BottomCTA)**. 제목 블록은 위아래 24px, 제목과 부제 사이 4px이에요.
- 목록 행은 왼쪽 24px, 오른쪽 16px, 위아래 16px이에요.
- 간격은 4px 배수를 쓰세요(`space-4`~`space-24`).
- 카드를 줄줄이 쌓지 말고 **흰 배경 위 목록**을 기본으로 쓰세요. 여러 서비스를 모아 보여주는 홈 화면에서만 `greyBackground` 위에 흰 카드를 올리세요.
- 여백은 넉넉하게 두세요. 한 화면에 정보가 적으니 빈 공간이 남는 게 정상이에요.

### 모서리

- 크게 둥글리고, 요소가 클수록 더 둥글게 하세요: 버튼 `radius-button-small` 8 → `radius-button-medium` 10 → `radius-button-large` 14 → `radius-button-xlarge` 16, 다이얼로그 `radius-dialog` 24, 바텀시트 `radius-sheet` 28.
- 한 줄 토스트, 칩, 스위치는 `radius-full`(알약형)이에요.
- 화면 아래에 붙는 전체 너비 버튼만 모서리가 0이에요.

### 그림자와 층

- **그림자는 거의 쓰지 마세요.** 층은 딤(`dimmedBackground`)과 배경색 차이로 나눠요.
- 쓸 때는 `shadow-float`(토스트, 팝업)과 `shadow-control`(작은 떠 있는 컨트롤)만 써요.
- 테두리로 상자를 그리지 마세요. 입력 칸도 옅은 배경(box형)이나 밑줄(line형)로 표현해요.

### 상태

- **누름**: 버튼·스위치·칩은 `press-scale`(0.96배)로 즉시 줄어들어요. 목록 행은 행 안쪽 4px 6px에 `radius-press` 12px 둥근 사각형이 `greyOpacity100`으로 나타나요.
- **비활성**: fill 버튼과 스위치는 `opacity-disabled`(0.3). 주요 버튼은 회색이 아니라 옅은 파랑으로 보여요.
- **포커스(입력)**: 밑줄형은 밑줄이 `blue400`, 라벨이 `blue600`. box형은 파란 막(`blue900` 5%)이 덮여요.
- **오류**: 라벨·도움말·밑줄이 `red600`. 오류 문구는 입력 칸 바로 아래에 해결 방법으로 써요.
- **로딩**: 버튼은 글자 대신 점 3개. 콘텐츠는 레이아웃 모양 그대로 스켈레톤.
- **키보드 포커스**: `focus-ring`(배경색 2px 간격 + `blue500` 2px).

### 모션

모든 움직임은 스프링처럼 빠르게 시작해 부드럽게 멈춰요. 수치는 "모션" 섹션에 있어요. 장식용 애니메이션은 넣지 말고, 완료·적립처럼 좋은 순간에만 체크나 축하 연출을 넣으세요.

## 아이코노그래피

- 이 시스템에는 **아이콘 파일이 없어요.** 토스 아이콘 세트는 공개되지 않았어요. 둥근 끝과 둥근 모서리를 가진 단순한 채움형 또는 선형 아이콘으로 대신하세요.
- 아이콘 크기는 `icon` 24px, 작은 글자 옆은 `icon-small` 20px. 색은 `grey400`~`grey600`, 강조할 때만 `blue500`.
- 목록 오른쪽 꺾쇠(›)는 `grey400`으로 약하게.
- 토스는 자체 이모지 서체 **토스페이스(Tossface)** 를 목록 아이콘, 빈 상태, 알림 앞에 써요. 무료 공개(github.com/toss/tossface)라서 쓸 수 있으면 그걸 쓰고, 없으면 시스템 이모지를 하나씩만 쓰세요.
- 혜택·이벤트 화면에는 동전, 지갑, 선물상자 같은 부드러운 조명의 입체(3D) 오브젝트가 어울려요. 사진이나 얼굴 일러스트는 거의 쓰지 않아요.
- 은행·카드사는 원형 로고 자리에 두세요. 실제 로고가 없으면 이니셜을 넣은 `grey100` 원으로 대신하세요.

## 컴포넌트

`window.TossStyle`에 React 컴포넌트 11개가 있어요: `Button`, `BottomCTA`, `Top`, `ListRow`, `Border`, `TextField`, `Switch`, `Badge`, `Toast`, `ConfirmDialog`, `BottomSheet`. 각 카드에 쓰는 법과 TDS 수치가 있어요.

TDS에는 이 밖에도 `Checkbox`, `Tab`, `SegmentedControl`, `Chip`, `Skeleton`, `NumberKeypad`, `Result`, `ProgressStepper`, `AgreementModule` 등이 있어요. 여기에는 아직 없으니 토큰으로 조합하세요. 칩은 높이 `button-small`·`button-medium`, `radius-full`, 간격 6px로 만들어요.
